Ticket: SWM-309. PR agent-ix/ix-relay#68 at `a0cdbcdbd1c3f62272c45c2339b1638732ee1e33`. Base checklist over the added FR-071 section, FR-071-AC-12, the TC-071-12 row and the matrix totals. ## Verdict

**FAIL**: the row definition omits a field of the agreed consumer contract; two further statements need correction.

## Findings

| ID      | Severity | Summary | Refs |
| ------- | -------- | ------- | ---- |
| FND-001 | high | The required row fields omit `expired`, which the contract agreed with ix-board (SWM-261) lists beside `state` and the ticket asks for. State the field and its rule (for example whether it stays true for an order acted after `AckExpired`, and what it is for an open order past its deadline). | spec/functional/FR-071-order-ack-deadline-and-timeout.md:85-91 |
| FND-002 | medium | `oldest_available_at` is required to be the oldest time with complete data, but the section says nothing about senders that predate the index, so the statement cannot hold during a rolling upgrade. The expired-orders section states its mixed-version limit; this one needs the rule the relay follows and the upgrade order. | spec/functional/FR-071-order-ack-deadline-and-timeout.md:93-97 |
| FND-003 | medium | `receipt_target` is defined as "the stored message target", which reads as the message's `to` address, the value `recipient` carries. The code returns the session queue key (`session/<machine>/<session>`), the receipt event target. Name that value so two implementers cannot read it differently. | spec/functional/FR-071-order-ack-deadline-and-timeout.md:85-86 |
