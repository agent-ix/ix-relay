# SR-6130: Code review — ix-relay SWM-309 all-outcome order listing

## Summary

Ticket: SWM-309. PR agent-ix/ix-relay#68 at `a0cdbcdbd1c3f62272c45c2339b1638732ee1e33`, reviewed as `git diff origin/main...HEAD` (merge base equals origin/main `81bb0040`). The rust-review lane is folded into this file.

Evidence: macOS, temporary local `redis-server` 8.10.2 on 127.0.0.1, `CARGO_TARGET_DIR` inside the ticket worktree. `cargo fmt --all --check`, `cargo clippy -p relay-core -p agent-msg --all-targets --locked -- -D warnings`, `cargo deny --locked check licenses sources` and `check-test-matrix` pass. `agent-msg --test send_order` 6/6, `relay-core --test orders` 21/21, `relay-core --lib receipt` 1/1 and `send` 3/3, `relay-watcher order` 4/4 pass. A temporary scratch test (removed afterwards) drove the public API. The new command was also run once, read-only, against the live bus: it exited 1 with `invalid order history response`. No CI workflow file changed.

## Verdict

**FAIL**: four high findings. The command errors on every empty result (including the live bus today), omits the agreed `expired` field, and reports complete coverage while orders from older senders are missing.

What holds: the read runs as one `no-writes` script with no key scan and reads at most 501 index members and 501 order hashes (a 500-row page took 3 ms). Pagination over 2,050 orders from eight concurrent writers, with same-millisecond bursts up to 13, returned no duplicate and no gap at page sizes 1, 3, 7 and 500. `deadline_at` equalled the `orders-due` score for delivered, late-delivered and never-delivered open orders and the expired index deadline after expiry, including delivery after expiry. 10,003 orders listed with the 3 evicted ones as `evicted`. No body or credential appears in the output. `receipt_send.lua` refuses a wrong-typed index before writing. `quire trace` lists the four `implements` tags and the one `verifies` tag.
